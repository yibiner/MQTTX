# MQTTX Plus 功能与限制

面向使用者的说明：这个客户端比官方 MQTTX 多了什么、在哪里操作、边界在哪里。技术细节（变量解析链、序列引擎内部、MCP 协议）另见 [`mqttx-plus-agent.md`](./mqttx-plus-agent.md)。

## 这是什么

MQTTX Plus 基于官方 MQTTX 桌面版 v1.13.1 分支开发。基础部分（连接、发布、订阅、MQTT 5 属性、TLS、WebSocket、日志、编解码）与官方一致，上游文档同样适用。

在此基础上加了四类能力：

1. **连接级自动化** —— 自动订阅、自动回复、消息序列、定时消息，挂载在连接上，不依赖你停留在哪个页面。
2. **模板变量** —— `app/${productType}/${clientId}/device/service/sub` 这样带占位符的主题和报文，发送时按连接上下文填写。
3. **预设管理** —— 服务器、客户端、Topic、消息、消息序列、全局变量六类可复用配置。
4. **本机 Agent 桥接** —— 把当前这条连接以 MCP 暴露给本机的 AI Agent 临时验证。

数据与官方 MQTTX 完全隔离：独立 Bundle ID `dev.yibin.mqttxplus`，独立数据目录 `~/Library/Application Support/MQTTX Plus`，可以同时安装、互不影响。

## 一、连接级自动化

自动订阅、自动回复、消息序列在连接详情的「自动化」对话框里，分三个标签页；定时消息在发布面板里启动。

### 自动订阅

连接成功后按分组订阅，每组可配置：

- 多条 topic，逐条或合并成一个 SUBSCRIBE 包发出；
- 组内延时（毫秒，带 0 / 500 / 1000 / 2000 快捷值），用于模拟设备逐渐上线；
- 启用开关。

自动订阅创建的行在订阅列表里带「自动」角标。手动修改该行后角标消失，表示它已归你接管，不再跟随分组配置。删除分组不会删除已经建立的订阅行，那些行会变成普通订阅，之后连接时是否恢复取决于设置里的「自动重订阅」。

### 自动回复

按「主题过滤器 + JMESPath 条件」匹配收到的消息，命中后发出一条回复：

- 条件为空表示该主题的每条消息都命中；
- 回复内容两种模式：`fixed` 原样发送配置的报文，`echo` 把配置的字段合并进收到的 JSON 对象；
- 可设延时（0 / 100 / 500 / 1000 ms 或自定义）；
- 可对变量做动作：重置某些变量、把报文里的字段捕获到变量里。

匹配基于服务端发来的原始报文，脚本或 Schema 转换后的内容不参与匹配。

### 消息序列

一条序列由若干步骤组成，每步有自己的延时、主题、报文、QoS 和变量赋值：**延时是相对上一步的**，不是绝对时间点。步骤发出的报文里可以引用变量，发出后再把赋值写回，所以 `${water - 20}` 在报文和赋值里是同一个数字。

每一步有两个预设入口，填的范围不一样。报文框上的消息预设把这条消息的主题和报文一起写进当前步，延时、QoS、Retain 和赋值不动。主题框上的 Topic 预设只更换主题。两个都用过之后，后选的覆盖它负责的字段，手改仍然有效。新建连接、编辑连接、序列预设和客户端预设里的步骤都是这一套。

触发方式三种：

| 触发 | 说明 |
| --- | --- |
| 手动 | 在连接页点「运行」 |
| 连接时 | 连接成功后自动跑 |
| 收到消息 | 主题与 JMESPath 条件命中后跑，可用 `${msg.x}` 引用触发报文 |

序列可以循环，并设置停止条件：某轮结束后读一个变量的值，满足比较条件就停。

三条实际行为需要知道：

- 同一条序列再次触发，会取消上一轮还没发出的步骤，从第一步重来。
- 断线会取消未完成的步骤，重连后不会自动续跑；连接时触发的序列会在重连后重新开始。
- 步骤报文由引擎直接发出，不经过发布面板的脚本与 Schema 管线。需要脚本处理的报文请用定时消息或手动发送。

### 定时消息

固定间隔重复发送启动时捕获的报文，间隔最小 1 秒。每条连接最多同时运行 10 个。

每次发送都会重新解析变量，所以 `${timestamp}` 每次都是当前时间，计数器每次前进一步。单条连接断开或你点停止时取消。

如果报文需要发布脚本、Schema，或带 MQTT 5 属性，定时任务依赖连接页面处于打开状态：离开页面时任务暂停，回来继续，不会退化成另一种发送方式。

## 二、模板变量

任何填写主题或报文的地方都支持 `${name}`：

```text
topic:   app/${productType}/${clientId}/device/service/sub
payload: {"water":${water - 20},"ts":${timestamp}}
```

### 变量种类

| 种类 | 值的变化 |
| --- | --- |
| 常量 | 固定文本，本身也可以嵌套变量 |
| 计数（sequence） | 每次发送按 step 前进，可设上下限与越界策略 |
| 随机 | 每次发送在区间内取值，可设种子复现 |
| 随机游走 | 在上一次的值附近浮动，限制在上下限内 |
| 权重选择 | 按权重从若干选项中取一个 |
| 会话 | 每次连接生成一次，UUID 或模板 |
| 捕获 | 由自动回复动作写入，配置值作为默认 |
| 开始时间 | 该连接上的消息序列启动时写入时间戳，同一轮保持不变 |

### 作用域与重置

变量可以定义在两处：

- **全局变量**（预设管理里）：所有连接共用一个值；
- **客户端变量**（连接或客户端预设里）：每条连接各自一份，两条连接互不干扰。

重置触发条件包括连接成功、断开、应用启动、手动点击、越界；还可以设置每隔若干秒惰性重置。自动重连是否算作一次「连接成功」可以单独控制。

`${startAt}` 这类开始时间变量只在**连接作用域**生效，全局定义的不会被写入，避免一条连接启动就改了所有连接的时间。

### 表达式与未解析

占位符里可以做四则运算：`${water - 20}`、`${ts-34000}`、`${msg.data.list[0].id}`。运算走 JavaScript 数字，超过 2^53 的整数在表达式里会丢精度，直接当文本注入则保持原样。

变量可以嵌套引用，最多展开 10 层，循环引用会报错而不是死循环。

解析不出来的占位符不会被静默发送：手动发送会弹确认框，自动回复会跳过该条规则并记日志，Agent 发送直接报错。

## 三、预设管理

左侧「预设」页面有七个标签：

| 预设 | 用途 |
| --- | --- |
| 服务器 | 复用 Broker 地址与端口 |
| 客户端 | 复用 Client ID、认证信息、变量与自动化规则 |
| Topic | 复用带变量的主题模板，任何填主题的地方都能选 |
| 消息 | 复用主题和报文。发布面板选一条填入；消息序列的每一步也可以选，同时填入该步的主题和报文 |
| 消息序列 | 复用整套序列。新建连接、编辑连接和客户端预设里，通过「插入预设」从列表选一条加入 |
| 自动回复 | 复用一组回复规则，一条预设里可以添加多条。新建连接、编辑连接和客户端预设里通过「插入预设」整组加入。不带示例，避免连上之后就回复真实流量 |
| 全局变量 | 跨连接共用的变量 |

预设填入后仍可编辑，改动不会回写预设本身。Topic 预设只保存模板，不保存解析后的字符串，所以同一个模板能服务所有连接。

消息序列预设首次启动会带两个示例（水量循环、OTA 进度），删掉后不会自动重建。自动回复预设不带示例。

## 四、暴露给本机 Agent

连接详情顶部有个连接图标，点开是「暴露给本机 Agent」开关。

打开后，MQTTX Plus 在本机 `127.0.0.1` 上启动一个 MCP 服务（默认从 21883 开始找可用端口），Agent 通过它调用**当前屏幕上这条连接**：

- 发出的消息出现在这条连接的消息列表里，并带 Agent 标记；
- 读到的消息不受界面方向标签、主题筛选、搜索框和滚动位置影响；
- 可以启停这条连接上已配置的消息序列，步骤和延时仍由应用执行。

面板上有两个按钮：「复制配置」得到原始 MCP JSON，「复制配置给 AI Agent」得到一段可以直接粘贴给 Agent 的说明，让它自己装好配置并回读当前可调用的客户端信息。

## 五、限制清单

### 通用

- 消息列表在内存里保留最近 40 条；更早的消息从本地数据库按需加载。
- 「忽略 QoS 0 消息」打开后，QoS 0 消息不写入本地数据库，重启后不可回查。
- 发布历史最多保存 200 条（默认 20 条），保存的是主题 + 报文，不是完整报文属性。
- 单条报文显示上限 16 KB – 2 MB 可调，默认 512 KB，超出部分不渲染。
- 最大重连次数默认 10 次。

### 自动化

- 定时消息：每条连接最多 10 个，间隔最小 1 秒；需要脚本 / Schema / MQTT 5 属性时依赖连接页面打开。
- 消息序列：延时相对上一步；断线取消且不续跑；步骤报文不经过脚本与 Schema；每秒超过 20 步会被判定为空转并停止；序列自己发出的报文在 5 秒内不会被自己再次匹配，避免自触发。
- 自动回复：每秒最多 20 条；同一个报文（按连接 + 主题 + packetId + 规则）在 60 秒内只回复一次，重投递不会重复回；回复发出的内容在 5 秒内不会被当作新消息再次匹配，避免自触发循环；匹配依据是原始报文。

### 变量

- 展开深度上限 10 层。
- 表达式内的大整数会丢精度（见上文）。
- 可变变量的值写在本地文件，写入有 500 ms 合并，两个窗口同时读可能短暂读到同一个值。

### Agent 桥接

- 只服务**当前聚焦窗口正在显示**的那一条连接。切换连接后，后续调用作用到新连接；想同时调两条连接做不到。
- 只监听回环地址，凭据是本地生成的 Bearer Token；不支持远程访问，也没有 TLS。
- 带旧 `connectionId` 的调用在切换连接后会失败，不会误发到另一条连接。
- `list_messages` 每次最多 100 条，默认 30 条。
- `wait_for_message` 单次最多等 60 秒，默认 10 秒。
- Agent 发送固定按纯文本处理，不支持十六进制 / Base64 / CBOR / MsgPack，也不支持 MQTT 5 属性。
- Agent 不能改订阅、变量、自动回复和序列定义，只能启停序列。
- 页面关闭或切换到别的连接时，还在等待的调用会收到明确的结束提示。

## 六、本地数据

| 内容 | 位置 |
| --- | --- |
| 连接、消息、订阅 | 应用数据目录下的 SQLite |
| 预设、全局变量、Agent Token 与端口 | 应用数据目录下的 `config.json`（electron-store） |
| 可变变量的当前值、各连接的会话状态 | 应用数据目录下的 `variable-state.json`（独立文件） |

应用数据目录：macOS 为 `~/Library/Application Support/MQTTX Plus`。与官方 MQTTX 的 `MQTTX` 目录互不读取，卸载任一不影响另一个。

同一时间只应运行一个 MQTTX Plus 进程：预设和变量状态写在同一个应用数据目录里，两个进程会互相覆盖。

## 七、已知取舍

- **一条连接一个视图**：界面同一时刻展示一条连接，其他连接可以保持在线，但 Agent 桥接只跟随聚焦窗口。需要同时观察两条连接时用「新窗口」分别打开，Agent 仍然只打最后一个获取焦点的窗口。
- **变量运行状态是尽力一致**：写入合并 500 ms，跨窗口不做强一致。
- **消息读取依赖连接页面**：桥接的读消息来自页面记录的到达消息 + 数据库，页面不在时桥接没有目标。
- **QoS 0 与存储的取舍**：开启「忽略 QoS 0」换性能，代价是这部分消息重启后查不到；Agent 桥接在页面存活期间仍能看到它们。
